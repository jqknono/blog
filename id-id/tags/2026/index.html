Rekomendasi Penggunaan Claude Code untuk Model Domestik

  1. Blog
  2. Rekomendasi Penggunaan Claude Code untuk Model Domestik

Saya sebenarnya sedikit tidak nyaman dengan perusahaan ini, Anthropic, tetapi karena popularitasnya sedang tinggi, saya hanya bisa menggunakannya sambil menahan napas. Saya membeli langganan Claude Code Pro, alasannya sangat terbatas, jadi saya hanya bisa menggunakannya secara terencana. Performa model domestik meskipun sedikit lebih buruk, tetapi kuotanya lebih banyak, keuntungan nilai jelas. Penjual model domestik saat ini belum menyediakan response API, sehingga tidak dapat terintegrasi dengan baik ke dalam Codex, asalkan kita tidak mempertimbangkan Codex lama. Chat completion mungkin memiliki batasan historis, sehingga performa berbagai API tidak sepenuhnya konsisten, seperti DeepSeekV4 membutuhkan extra body membuka thinking, hanya mengakui “high/max”, dan dalam multi-turn dengan tools perlu mempertahankan reasoning_content. Untuk Zhipu, temperature tidak boleh diatur ke 0. Untuk Kimi, dengan thinking, temperature harus tetap 1, tidak mendukung tool_choice=required, tidak mendukung functions, dll. Jadi OpenAI API chat completion belum menjadi standar faktual, langsung mengintegrasikannya akan ada kompromi di beberapa skenario, dan yang serius dapat error sehingga tidak dapat berlanjut. Sebaliknya, mereka kompatibilitas terhadap Anthropic API, meskipun masih ada beberapa skenario yang tidak kompatibel, tetap berusaha menjaga kompatibilitas. Oleh karena itu, menggunakan Anthropic API secara langsung adalah pilihan yang mudah. Sedangkan Claude Code sebagai produk resmi Anthropic, memiliki hak mutlak atas perubahan API Anthropic; penjual model tidak ingin mengabaikan pengguna Claude Code, maka mereka harus berusaha adaptasi. Ini adalah pilihan hemat yang sesuai saat ini, semoga di masa depan ada API yang lebih umum, sehingga benar-benar memisahkan model dan alat.
